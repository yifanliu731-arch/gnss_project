# SeaArrayCalib 使用说明

[English version](user-guide.en.md) · [项目首页与安装说明](../README.md) · [模型细节](model.md) · [CSV格式](data-format.md)

SeaArrayCalib 是用于 GNSS–声学（GNSS-A）航迹规划和海底信标标定的本地网页工具。它把阵列、航迹、声学观测安排、声场假设和联合估计放在同一流程中，帮助用户比较“怎样走、需要多久、在给定假设下预计怎样”。本文介绍当前网页可直接使用的功能。

## 1. 能做什么

网页分为“航迹设计”和“实测数据”两个工作区，可随时切换中文／EN。同一页面会话中，语言切换保留输入、上传文件和已有结果。

**航迹设计可以：**

- 输入1–64个信标的三维坐标，调整数量、布局和深度。
- 比较圆、八字、三叶草、方形、四瓣玫瑰、圆加十字六类完整航迹，搜索尺度和方向。
- 按船速、完整航程、串行声学询问、设备斜距和观测覆盖生成候选；在十档航时预算内选取方案。
- 采用无需上传资料的 Munk 声场，或用户给定的背景及带日期的历史声速剖面。
- 比较名义精度、平均声场风险和规定扰动集合内的最坏方向风险；独立调整设计风险半径。
- 用固定轮数或目标航时差细化候选尺度；查看几何、评分、联合解算、缺测和失败原因。
- 在剖面模式下，用训练日期选轨，再对一个或全部留出日期进行验证。

**实测数据可以：**

- 读取 GNSS、声学走时和声速剖面三个 CSV，识别信标编号并预览资料。
- 默认对所选信标进行多信标联合标定；也可选择同模型单信标拟合，或界面列出的其他求解器。
- 使用测得姿态旋转 GNSS 天线至换能器的杆臂，输出信标坐标、内部精度、走时残差及拟合参数。
- 查看地理／局部坐标航迹、原始点和平滑显示曲线，并按需要导出结果。

这两个工作区回答不同问题：航迹设计比较预先生成的作业方案；实测数据处理当前上传的一组航迹观测，不会自动把它变成多条候选航迹再做风险排序。

<a id="startup"></a>
## 2. 安装与启动

Windows 首次使用需要 Python 3.12 和 Node.js 22.12或更新的22系列版本。在项目文件夹打开终端，依次执行：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm ci
.\start_all.bat
```

完成首次安装后，直接双击项目中的 `start_all.bat`。浏览器访问 [SeaArrayCalib 本地页面](http://127.0.0.1:5173/)。页面服务使用5173端口，计算服务使用8000端口；启动日志保存在项目的 `.run/` 文件夹。启动器不会自动安装依赖。

停止服务时，在项目文件夹执行：

```powershell
powershell -ExecutionPolicy Bypass -File stop_web.ps1
```

macOS／Linux 手动启动步骤见[README](../README.md)。结果保存在当前计算服务的内存中，重启前应先导出；页面刷新也不应当作保存结果的方式。

<a id="first-run"></a>
## 3. 第一次运行仿真

1. 进入“航迹设计”，选择“理想 Munk 模型”。这种模式无需上传声速文件。
2. 检查信标坐标。初始为四信标6 km × 6 km阵列，E/N为±3000 m，深度分别为3150、3180、3220、3250 m。U向上为正，因此海底坐标应为负值。
3. 检查右侧“航迹设置”。当前界面初值为3 kn、5–25 h预算、八个初始尺度、四个方向、一轮细化、C3、ρ=1和10 km可用斜距。
4. 首次只熟悉操作时，可以只选一种形状、将180°等分数设为1、初始尺度数设为3、细化设为0，减少计算量。进行正式比较前再选择适合任务的范围和搜索密度。
5. 按实际设备设置可用斜距、采样间隔和噪声。默认演示值不会根据声纳频率自动推断实际设备性能。
6. 点击“运行仿真”，查看进度和错误说明。初次计算可能包含数值函数编译时间。
7. 完成后切换航时预算，再查看A／B／C方案、候选列表、坐标估计及拟合状态，最后导出。

“重置”位于阵列编辑区，只恢复初始四信标坐标，不代表所有作业参数都恢复默认。更改输入后，已有结果仍属于运行时保存的配置，需要重新运行才能得到新设置的结果。

<a id="settings"></a>
## 4. 阵列、航迹与作业参数

### 阵列和杆臂

坐标单位为米，采用东、北、天（ENU）。航迹默认以当前阵列的水平几何中心为中心；搜索形状、尺度和方向，不搜索中心偏移。允许输入的信标数量上限不代表任意阵列都可可靠解算。

杆臂是“换能器相对于GNSS天线”的位移，按船体右／前／上（RFU）输入，向下为负。仿真以航迹航向旋转杆臂；实测模式使用文件中的姿态。两个工作区的杆臂初值服务于各自示例，应根据实际安装修改。

### 六类完整航迹

圆、八字、三叶草、方形和四瓣玫瑰是闭合航迹。圆加十字依次执行一圈圆和两条正交直径，并包含一段直线转场；到最后终点结束，不强制回到起点。转场总是计入船时，“直线转场采样”默认关闭。

尺度定义为航迹相对中心的最大径向范围。方形的边长等于该范围的√2倍。尺度输入是平均信标水深的倍数：默认0.5–10倍；例如平均水深3200 m时，对应1.6–32 km。数值搜索可以生成较大的几何，但超预算或不满足观测条件的候选不会成为合格方案。

“180°等分数”控制方向：1对应0°，2对应0°／90°，4对应0°／45°／90°／135°。圆形的角度改变起始相位，其他形状主要体现为旋转。航行顺序固定，细化不会另外优化绕行顺序。

### 船速和预算

默认船速为3 kn，约1.5433 m/s；切换单位保留相同物理速度。最短和最长预算以小时输入，支持0.1–48 h，且最短必须小于最长。程序生成包含两端点的十档对数等距预算。

预算是完整作业时间的上限，入选航迹可以更短。程序不会截断路线、额外绕圈或虚构等待来填满预算。预算切换复用同次运行的候选和观测，不会为每一档重新抽取噪声。

### 采样、覆盖和噪声

- 采样可按Hz或秒／次输入。声学询问按信标串行轮询，每个时隙只对应一个信标；实际时隙还受保守双程传播占用及1秒应答余量限制，因此请求更高频率不一定增加观测。
- 可用斜距是换能器与被询问信标之间的三维直线距离门限。超过门限时排除该条观测；同一阶段对其他信标的观测按自身条件判断。
- 声线支持、丢测及每信标覆盖也会影响可行性。当前要求每个信标至少有八条有效观测，仍须通过其他几何和估计检查。
- 仿真的声学时间噪声输入单位是**秒**，初值0.0001 s；GNSS噪声单位是米，初值0.05 m。实测页面的时间噪声输入使用**毫秒**。
- Munk 模式可调整水平声速梯度、时间变化强度和相关时间。剖面模式使用上传资料，这些解析扰动控件不参与该模式计算。
- 随机种子用于复现给定配置。改变候选集可能改变共同随机场的时间节点，因此不能仅凭种子相同认为不同搜索配置的全部随机样本逐项相同。

<a id="risk"></a>
## 5. C1、C2、C3与风险半径

**C1：名义坐标方差。** 在所用模型、噪声和声学参数先验下，衡量联合坐标估计的名义不确定性。

**C2：平均坐标风险。** 在C1上增加由规定声场扰动二阶矩传播得到的平均环境影响项。

**C3：最坏方向坐标风险。** 在C1上增加规定椭球扰动集合内最不利方向的坐标影响项。

同一准则下分数越小越优，单位为m²。它们是设计阶段的预测量，不是每次实际误差的保证值。较低C3不保证每个验证日期都比其他方案误差小。

### 设计扰动倍数／风险半径ρ

ρ独立控制设计风险，默认1，允许0–100。它主要用于比较 Munk 模式下的风险假设，也适用于上传剖面；上传剖面时建议保持1，以采用训练资料导出的扰动尺度。

- ρ=0：C2、C3退化为C1。
- ρ=1：使用基准设计扰动尺度。
- ρ=2：C2、C3的**环境项**变为原来的4倍，C1本身不变。

ρ只改变设计评分和最终选轨，不放大验证声场、噪声或缺测，也不改变估计器。为了在改变ρ时保持共同候选池，局部细化始终按ρ=1的C1／C2／C3进行，最终用用户设置的ρ重新评价这份池。

剖面模式另有“剖面异常倍数”，支持0.5、1、2、5倍。这个值同时改变训练风险幅度和验证声速异常，含义不同于ρ。希望保持上传资料原有幅度时，两个倍数均选1；只检查设计对风险假设的敏感性时，保持剖面异常倍数为1，仅调整ρ。ρ不是置信概率，也不是允许的定位误差上限。

<a id="refinement"></a>
## 6. 固定轮数与目标时间差细化

候选首先来自用户尺度范围内的对数间隔点，并补入对应完整航时预算的边界尺度。之后才按所选细化方式加点。**旧候选始终保留，新候选与它们一起参与后续比较。**

### 固定轮数：0、1、2、3

0表示仅使用初始点和预算边界，不进行局部细化；默认1轮。每轮分别在各形状、方向、预算以及ρ=1的三种准则下选择优选尺度，找出其紧邻的较小和较大尺度，在两侧加入对数中点，合并重复候选。

例如当前优选尺度为2、邻居为1和4：第一轮新增√2≈1.414、√8≈2.828。如果第二轮仍是2最优，就在2与新邻居之间继续加约1.682和2.378。若优选尺度改变，下一轮随新的评分结果选择邻域。固定两轮时，做完两轮就停止；优选值一直不变不会使它无限细化。

### 细化至目标时间差

在下拉框3轮之后选择“细化至目标时间差”，出现“最小时间单元（分钟）”，默认**5分钟**，允许0.1–2880分钟。

程序仍使用上述对数中点规则，但只继续细化当前优选尺度与相邻尺度之间、**完整走航时间差大于目标**的区间。每轮重新选优，直到所有当前可细化的优选邻域满足目标。完整时间包括转场，数值大小也会随船速变化。

这里的5分钟不是计算耗时、采样间隔或距预算上限的余量；它约束优选尺度附近的候选航时差，并不要求整个尺度网格都细到5分钟。较小目标通常需要更多计算，也不等于连续全局最优或评分已经收敛。

结果显示实际细化轮数、目标和剩余最大邻域间隔。没有可细化邻域会单独报告，不冒称已达到目标。超过2000条候选，或30轮仍未达到目标时，程序明确报错；可减少形状、方向或初始尺度数，缩小尺度范围，或增大目标时间差后重跑。

<a id="profiles"></a>
## 7. 背景＋历史剖面仿真

### 用内置南海资料上手

1. 在“航迹设计→声场模型”选择“背景＋历史剖面”。
2. 点击“加载南海测试样例”。它替换背景、历史剖面及日期划分，不修改阵列、设备量程或航迹设置。“下载样例文件”只下载ZIP，不改变当前输入。
3. 检查统计：样例含2020年前182天训练、14天空档、后170天验证。训练截止和验证开始日期均包含当天，中间日期不参与训练或验证。
4. 初次保持剖面异常倍数1、ρ=1，验证范围选择单个留出日期，并指定详细解算日期。
5. 点击“检查剖面”，确认文件、深度和日期有效，再检查作业设置并运行。
6. 熟悉结果后，可选“全部留出日期”。计算量随入选的不同航迹及日期数增加。

样例历史资料是经过背景对齐的再分析日剖面，包含明确的数据加工和深层假设，不是逐日CTD实测。它采用回顾性时间留出；资料来源及处理见[样例说明](../examples/south_china_sea_profiles/README.md)。

### 上传自己的两份CSV

背景字段为 `depth_m,sound_speed_mps`；历史字段为 `date,depth_m,sound_speed_mps`，日期写成 `YYYY-MM-DD`。深度向下为正，单位米；声速单位m/s。按同一海区、兼容基准准备两份资料，历史减背景即定义异常。

两份文件均须从深度0开始，有共同的充分深度覆盖，至少达到最深信标以下100 m。程序保留各输入深度节点，分段线性插值到共同网格，不自动平滑、抽稀或向深处外推。重复日期／深度、缺失值等会被拒绝。每文件上限16 MiB；进一步数据规模限制见[模型说明](model.md)。

手动上传只替换对应输入，不会自动替换另一个文件；确认页面标注的文件名和来源。资料或日期变化后，统计自动更新，计数反映文件中实际存在的剖面，而不只是日历天数。

### 验证如何进行

只有训练剖面参与风险建模、评分和选轨；验证误差不用于重新选择。每个验证日期的声速剖面在整次航行中保持静态，所有比较方案使用同一个日剖面。选中的相同航迹／日期只求解一次并复用。

所有候选保留设计评分，只有入选方案开展留出验证；A／B／C备选方案还在详细日期求解。未被验证的候选显示“仅设计评分”。验证失败保留原方案及原因，不用成功的其他航迹替换。

## 8. 实测数据联合标定

### 准备三个文件

- GNSS：`Time_UTC,Latitude_deg,Longitude_deg,Altitude_m`；可附 `Pitch_deg,Roll_deg,Heading_deg`，角度单位度。高程应对应GNSS天线。
- 走时：`Time_UTC,Beacon_ID,Delay_s`，每行是一条对指定信标的观测，时间单位秒。使用本工具约定的单程等效走时；已有单程数据不要再除以2。
- 声速剖面：例如 `Depth_m,Velocity_mps`，亦接受样例的 `Depth (m),SV (m/s)`。深度向下为正，声速单位m/s。

使用带表头的UTF-8 CSV，保留原始UTC和缺口。GNSS应覆盖声学观测时段；联合／同模型单信标模式要求有效时间配准，不用行号代替时间，也不外推缺少的导航。姿态角可以用于杆臂旋转；只有姿态角不等于有完整惯性导航数据。

### 用实测样例运行

1. 进入“实测数据”，分别上传项目 `examples/large_circle_cross/` 中的 `gnss.csv`、`delay.csv`、`ssp.csv`。此样例需手动上传。
2. 检查预览和检测出的编号，选择 `2,5,6`。编号可用逗号或空格分隔；留空表示使用检测出的全部编号。
3. 保留默认“多信标联合求解（默认）”，即多信标联合标定模式。样例杆臂为右1.585 m、前6.716 m、上−29.05 m。
4. 检查时间噪声和GNSS噪声，当前实测初值分别为0.5 ms和0.05 m。
5. 点击“处理实测数据”，完成后检查各信标坐标、内部精度、走时残差、拟合参数和失败状态，再导出。

样例包含三个信标的4380条声学观测，圆形和十字来自不同时段，不应解释为一次连续走航。[样例详情](../examples/large_circle_cross/README.md)说明了来源、时间和配置。

### 联合与单信标模式的区别

默认联合模式同时估计N个信标的三维坐标，以及公共声速偏差、公共有效时延、线性时延漂移和N−1个相对时延，总计4N+2个参数。所选编号含B5时以B5为相对时延基准，否则使用最小编号。坐标均自由估计。

“单信标求解（逐站）”使用相同声线与估计模型，但对每个所选信标独立求解。界面还保留TOA和ESKF等求解选项，其参数化及输出含义不同；熟悉相应模型后再用于专门对照，不把它们的参数逐项视为联合模式的等价输出。

上传声速值按原分辨率使用，不平滑或抽稀。当前实测声线在最深输入点以下采用0.016 (m/s)/m线性延伸；这属于模型假设，应尽量提供足够深的剖面，并与仿真剖面模式“不自动外推”的规则区分。联合／同模型单信标模式不按拟合残差自动裁掉观测，输入质量控制应在准备资料时完成。

<a id="results"></a>
## 9. 怎样解读结果

### 两套不同的选择标签

C1／C2／C3定义“用什么分数评价”；A／B／C定义“在所选评分下如何权衡船时”。例如选择C3后：

- A：当前预算内设计分数最低的合格航迹。
- B：在分数不高于合格候选中位数的航迹中，选择航时最短者。
- C：把分数和航时分别按候选范围归一化，以相等权重选择折中方案。

因此方案C不等于评分C3。先确认当前评分、航时预算和保存的ρ，再解释方案。

### 可行性、拟合与误差

设计合格表示满足相关设计条件；验证成功表示后续拟合通过检查，两者分开记录。Munk 模式先确定推荐，再验证设计可行候选；某条推荐拟合失败时，仍保留推荐身份和失败原因。无合格方案的预算也保留显示。

仿真有已知坐标真值，可以报告坐标误差。剖面比较中的坐标MSE对3N个分量平均，单位m²；对应每信标三维RMS为√(3×MSE)。存在失败时，仅成功日期的平均值属于条件统计；C1–C3成对结果还要求同一日期双方成功。单次或单日期运行不能代表长期统计性能。

实测通常没有独立坐标真值。走时残差是“观测−完整拟合预测”，图中单位ms；它不是坐标误差。坐标标准差是给定模型和噪声假设下的内部精度，也不是独立绝对精度。小残差本身不能证明几何条件好。

### 航迹显示

实测页面可切换原始离散点与平滑曲线。平滑只影响显示，不改变实际用于解算的观测和船位。淡色虚线表示导航缺口的连接，不表示这些缺口内存在观测。

<a id="export"></a>
## 10. 导出和保存

完成后使用“导出结果”，选择全部、前10项或自选，并勾选航迹坐标、观测、残差；实测及适用的剖面结果可包含原始输入文件。ZIP始终包含汇总CSV、设置及JSON，并为所选结果建立子文件夹。仿真还可单独导出运行JSON和当前方案观测CSV。

仿真前10项按照保存的准则、当前选中预算及GDOP条件排序；验证失败不会使原设计推荐被替换。“全部”保留失败候选及原因。剖面模式的逐日验证记录与详细日期观测分别保存，不把未验证候选当成已完成拟合。

实测前10项按成功信标结果的残差RMS排序，是当前上传轨迹中的信标结果排序，不是航迹C3或绝对坐标精度排名。选择附带原始文件时，原文件保留完整内容，包括未选信标的行。

导出使用已保存的计算结果，不重新运行。配置保存单位、随机种子及适用的输入来源信息；CSV／JSON字段名不会随中英文切换改变。建议保留整个ZIP而不只保存截图，并在重启计算服务前完成下载。

<a id="troubleshooting"></a>
## 11. 常见问题

**页面打开但无法计算：**检查8000端口的计算服务是否启动，并查看 `.run/` 日志；启动器遇到端口占用会报告，不应直接关闭未知进程。先确认是否已启动同一项目。

**当前预算没有合格航迹：**先查看候选原因，再核对完整航时、尺度、设备斜距、声线支持、每信标覆盖及GDOP。只有与实际设备／任务相符时才调整限制，不为得到结果任意放宽物理条件。

**细化太慢或超过候选上限：**减少同时比较的形状、方向或初始尺度数，缩小范围，或者改用较少固定轮数／较大的目标时间差。0轮仍有预算边界候选，因此最终数量可以大于界面显示的初始候选数。

**选择细化两轮，最好尺度没有变化：**程序仍执行第二轮；旧点保留。目标时间差模式则按邻域间隔判断是否继续，不以赢家是否换号作为停止条件。

**剖面检查不通过：**检查两份文件、字段、日期重叠／划分、重复深度、海面起点及最深信标以下100 m覆盖。训练和验证都必须有可用资料；检查统计而不只看日期区间。

**实测时间无法配准：**检查时区、UTC格式、重复或未排序时刻、GNSS时间覆盖。不要用重新编号时间或虚构GNSS点掩盖真实缺口。

**拟合失败或少了观测：**保留并查看具体原因。量程、声线、覆盖、几何和数值验收各有不同含义；数值验收失败不能单凭状态推断实际坐标误差大小。

**修改ρ后验证异常幅度没有变：**这是预期行为。ρ控制设计风险；要测试不同物理扰动幅度，在剖面模式调整“剖面异常倍数”，或在Munk模式调整相应声场参数。

**重启后无法导出旧任务：**任务结果存于服务内存，需使用重启前下载的ZIP；重新运行会创建新的任务。

<a id="scope"></a>
## 12. 建议的使用顺序与模型边界

先用小规模 Munk 搜索熟悉流程，再按设备与海域调整输入；有背景和历史资料时，检查剖面划分，以1倍异常、ρ=1完成单日验证，再开展所需的全日期评价。实测数据先核对单位、UTC、杆臂和声速深度，再使用默认联合标定。

SeaArrayCalib 当前进行有限候选搜索，风险是局部模型在规定扰动假设下的评价。剖面仿真采用单航次静态一维日剖面；Munk 模式采用规定的解析扰动。输出不自动建立真实三维海洋、实际设备性能或独立实测精度的证据。进行科学比较时应固定条件、保留失败和完整成本，并区分设计分数、仿真真值误差与实测内部指标。
